# 样品台账

本地运行的留样质检台账。记录来样登记、多管取样、混合分装、冻干保存、空白溶剂复溶、
报废和召回，按微升精确记账（Fraction / Decimal，不经二进制浮点），任何一次操作要么
整体生效，要么整体撤回。

台账同时记两本平行的账：**体积**和**原样折算量**。冻干只动体积，复溶按实测体积入账，
取样按体积占比带走折算量，两本账都能追溯到每一支来样。

## 启动

```bash
python3 app/server.py            # 默认 http://127.0.0.1:8000
python3 app/server.py --port 8123 --db data/ledger.sqlite3
```

只依赖 Python 3 标准库（SQLite 内建于标准库），不需要安装任何包。打开浏览器后
数据会写入 `data/ledger.sqlite3`，关掉再开继续用。

导出：

- `GET /api/export/inventory` → 库存 CSV
- `GET /api/export/recalls` → 召回清单 CSV

界面右上角也有对应下载按钮。

## 规则要点

- **精确用量**：所有量以 µL 记，收 `1000`、`12.5`、`1/3` 这类写法。小数按十进制
  字面值转成 `Fraction`，所以 `0.1 + 0.2` 精确等于 `0.3`；来源摊分可以是分数，
  中间不取整，界面用 "1/3" 或百分数展示。
- **总量守恒**：一次取样 / 分装必须满足「取样合计 = 分装合计」，否则整次拒绝。
- **完全混匀摊分**：一次操作取多管、出一支成品时，成品组成 = 各来源取样量占本次
  取样总量的比例。同一操作分出多支成品，每支按同样比例摊；历史详情里会逐支列出
  “该成品从每支来源管实际取了多少”。
- **整次原子**：先做完全部校验（编号冲突、来源存在、召回状态、用量是否足够、
  总量是否守恒）再写库，整个写库过程包在一个 SQLite 事务里。中途任何失败都回滚，
  不会出现“原管扣了量、新管没建出来”的半截状态。
- **状态**：管的状态按剩余量实时计算，四种——可用 / 已用尽（剩余 0 且是液体）/
  已报废（有报废记录）/ 召回中（在库且含被召回批次，禁取样）。已用尽、已报废
  和召回中的管都不能再取样。**干样体积记账为 0 但仍算在库可用**，可追溯、可复溶。
- **冻干保存**：液体管冻干后变成干样——体积这本账归零（不再是可移取的液体），
  **原样折算量原样保留**；干样仍在库、仍可追溯、仍受召回约束，但**干样不能直接移取**，
  取样会被拒绝并提示先复溶。
- **空白溶剂复溶**：用空白溶剂把干样复溶，**按实测体积入账**（界面/接口都要填实际加液量）；
  加的是空白溶剂，所以**原样折算量不变**。复溶后是液体，可按实测体积取样。
  一支管可以反复「冻干 → 复溶」，每次都在历史里留一条处理记录（处理前后物态、体积、
  折算量）。
- **按比例带走折算量**：从任何管（含复溶后的管）取样，带走折算量 =
  取用比例 × 该管当前剩余折算量；成品按分装量占比继承本次取走的全部折算量，
  因此折算量在取样/分装中守恒。混合分装时仍按完全混匀处理。
- **召回**：按来样批次发起。只标记发起时**仍在库且含该批来样**的管（含干样、含复溶后
  再分出的管），其他管、其他批次照常使用。召回记录永久保存发起时的受影响清单、
  当时物态、当时剩余量、当时折算量和当时组成；之后这些管被取用或报废，记录里的
  “当时”数值不变，同时会附上该管的当前物态与状态。
- **追溯**：
  - 按管：来源链（这管由哪些管按多少量混合而来，每段带物态）、当前组成（精确保留到
    每支来样，体积与原样折算量并列）、冻干/复溶处理记录（处理前后）、去向往哪些操作和成品。
  - 按批次：这批来样登记了哪几支管、流向哪些管（含经过多次混合、冻干、复溶的管）、
    每支管里这批来样占多少、折合当时多少 µL、折算量剩多少、现在剩多少；已用尽和
    已报废的也列出。
- **历史库存**：每个操作有自增的登记序号。`?seq=N` 可回看第 N 次操作完成时的
  库存、组成、物态与两本账；管的 `created_op` 之后的操作对它不生效。历史操作按登记
  先后列出，并保留每支成品的逐来源摊分。
- **持久化**：SQLite（WAL 模式），关掉进程再打开数据仍在。旧版（v1）数据库会在启动时
  自动升级：补齐折算量列并按液体状态回填，升级时 `initial_equivalent = initial_volume`。

## 概念

| 名词 | 含义 |
| --- | --- |
| 来样管（intake） | 登记的一支原始样品，绑定一个来样批次，组成为它自身 100% |
| 分装 / 混合管（pooled） | 由取样/分装操作新建的管，没有自己的批次，组成是各来样按比例 |
| 操作（operation） | 一次登记：来样 / 取样分装 / 报废 / 召回 / 冻干 / 复溶，序号即 `seq` |
| 组成（composition） | 从该管当前内容物可追溯到每支来样管的比例（精确分数） |
| 物态（form） | `liquid` 液体 / `dry` 干样；只有冻干、复溶会改变它 |
| 原样折算量（equivalent） | 这管内容折合多少「原始来样」的 µL。冻干不变、复溶不变（加的是空白溶剂），取样按体积占比带走 |
| 干样 | 冻干后的粉状管：体积账为 0，折算量仍在；仍算在库，可追溯、可召回，但不能直接移取，需先复溶 |

## 接口

| 方法 | 路径 | 说明 |
| --- | --- | --- |
| POST | `/api/intake` | `{code, batch, volume, note?}` 登记来样 |
| POST | `/api/split` | `{inputs:[{tube,amount}], outputs:[{code,amount}], note?}` |
| POST | `/api/lyophilize` | `{tubes:[code], note?}` 冻干（干样不能取样） |
| POST | `/api/reconstitute` | `{tubes:[{tube,volume}], note?}` 空白溶剂复溶，`volume` 为实测体积 |
| POST | `/api/retire` | `{tubes:[code], note?}` |
| POST | `/api/recall` | `{batch, note?}` |
| GET | `/api/inventory?seq=` | 库存（可指定历史序号） |
| GET | `/api/history?limit=` | 操作历史 |
| GET | `/api/operation?id=` | 单个操作详情（含逐成品来源摊分、处理前后明细） |
| GET | `/api/tube?code=&seq=` | 按管追溯 |
| GET | `/api/batch?batch=&seq=` | 按来样批次追溯 |
| GET | `/api/recalls` / `/api/recall?id=` | 召回记录 |
| GET | `/api/export/inventory` / `/api/export/recalls` | CSV 导出 |

所有量（体积、折算量）都以 µL 记，字段同时给出 `*_display`（人读写法）与精确值。

错误统一返回 `{"error": "...", "details": ["..."]}`，明细逐条说明是哪个字段 /
哪支管出的问题。

## 测试

```bash
python3 -I -m unittest discover -s tests -v
```

测试覆盖：分数精度、总量不一致回滚、用量不足回滚、编号冲突回滚、写库中途故障
回滚、嵌套混合组成、逐成品来源摊分、用尽/报废/召回拦截、召回当时快照、
历史序号回看、重开数据仍在、CSV 转义；冻干/复溶：干样仍在库且保留折算量、
干样禁取样、复溶按实测体积入账、复溶后取样按比例带走折算量、折算量在
「冻干 → 复溶 → 分装」链条上守恒、干样召回与召回后禁复溶、处理前后历史可查、
处理中途故障回滚、v1 数据库自动升级。
